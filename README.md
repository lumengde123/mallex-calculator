# MallEX 算力卡计算器

移动端优先的**纯静态**单页应用：输入你当前持有的算力卡、MEX 余额与日期，即可推算未来每一天的产出、余额、到期与可购买额度。

零依赖、零后端、零构建 —— 三个文件（`index.html` / `styles.css` / `app.js`）即可直接部署到任意静态托管。

## 功能

| 模块 | 说明 |
| --- | --- |
| 概览 | 当前余额、当前日产出、持有算力卡数、当前活跃度（及适用哪套规则） |
| 起始设置 | 起始余额、起算日（可改，用于复盘过去时段）、推算天数（35 / 45 / 90 / 135 / 365，或「自定义…」填 1–1500），以及起算日已有算力卡的录入：卡种、数量、起始日期、周期规则（自动 / 强制 35 天 / 强制 40 天） |
| 今日持有 | **只读**：列出今天实际持有中的卡、各自剩余天数、每张日产出与合计日产出 |
| 购买计划 · 手动 | 指定「某日买入某卡 × N」，按时间顺序参与推算；超过 3 条时列表在固定高度内滚动，**点任意一条可载入表单修改**（日期固定，其余可改） |
| 购买计划 · 条件自动 | 「余额 ≥ 买入价且仍有额度」时在生效区间内每天自动买入 1 张，可拖动排序 |
| M 币交易 | 右下角绿色「M 币」浮动按钮点开：买入 / 卖出 MEX（M 币即 MEX 的简称），数量直接加减余额，两个汇率只用来折算人民币，表单实时预览，改完表格立刻重算；超过 3 笔时列表内滚动，**点任意一笔可载入表单修改**（时间固定，其余可改） |
| 每日推算 | 未来逐日表格：日期、当日产出、当日余额、当日事件 / 持仓 / 可购；整个区间一次性展示，不分页 |
| 汇总 | 算力卡产出（不含 M 币买卖）、算力卡消耗（买卡投入）、算力卡盈余（产出 − 投入，带回报率）、M 币净额（卖出 − 买入） |
| 撤销 / 重做 | 顶栏 ↶ ↷ 或 Ctrl+Z / Ctrl+Shift+Z 回退任意一步输入 |
| 其他 | 一键导出 CSV、仅看事件模式、多存档、文本串导出（自动复制）与导入、自动本地存档、卡片折叠（默认展开）、撤销 / 重做、右下角浮动按钮（回到今天 / 直达底部或顶部 / M 币交易）、设置弹窗（省略过去数据、重置当前存档） |

所有输入改变后表格**实时重算**，无需点击按钮。

### 表格里有什么

「每日推算」的最后一列一天一行，从上到下三层：

```
事件        买入 初1 ×2 · 10.00 MEX      ← 这天发生的事（没有就省略）
持仓        初1×2 35天  精英×1 26天 活跃 201   ← 这天结束时的持仓、剩余天数、活跃度
可购        初1×6  初2×4  中级×4         ← 这天还能买什么（数字是剩余额度）
```

- **可购标签**：数字是「该卡剩余额度」，点一下就在该日买入 1 张。买得起才会出现（价格 ≤ 当日余额）。
- 同一张卡同一天点多次会合并为一条事件（`×2`、`×3`…），右侧「购买计划·手动」列表中同步出现可删除的条目。
- **买入事件**（青色标签）再点一下即**撤销 1 张**，减到 0 时整条事件消失。
- **持仓**里的 `26天` 是这张卡还剩多少天到期；同卡种有多张时，把每张的剩余天数都用 `/` 列出来，例如 `高级×2 31/40天`（一张还剩 31 天、另一张 40 天），超过 4 张只列前 3 个加省略号。
- **持仓徽章会变色**：最早到期的那张剩余 ≤ 7 天转琥珀，≤ 3 天转红，提醒快到期了。
- **活跃度**是当天持有卡 `活跃度` 字段之和，也是判定「35 天 / 40 天」的唯一依据（> 100 用 40 天）。
- **不分页**：整个推算区间一次性铺开，方便连续看趋势。区间太长时用各卡片右上角的「收起」把不需要的部分折起来。

## 规则与算法

### 两套算力卡规则

| 卡种 | 买入价 | 到期本息 | 额度 | 活跃度 | 每日产出（35 天） | 每日产出（40 天） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 初级1算力卡 | 5 | 6 | 8 | 0.5 | 0.17142857 | 0.15 |
| 初级2算力卡 | 10 | 12 | 4 | 1 | 0.34285714 | 0.3 |
| 中级算力卡 | 100 | 123 | 4 | 10 | 3.51428571 | 3.075 |
| 进阶算力卡 | 500 | 630 | 3 | 50 | 18 | 15.75 |
| 高级算力卡 | 1000 | 1290 | 2 | 100 | 36.85714286 | 32.25 |
| 精英算力卡 | 2000 | 2640 | 1 | 200 | 75.42857143 | 66 |
| 超级算力卡 | 5000 | 6750 | 1 | 500 | 192.85714286 | 168.75 |
| 专家算力卡 | 10000 | 13800 | 1 | 1000 | 394.28571429 | 345 |

- **旧版**：持有 35 天，适用于 11 月 1 日后、12 月 1 日前，且购买时算力活跃度 ≤ 100。
- **新版**：持有 40 天，适用于 12 月 1 日前活跃度 > 100 的情形。总本息不变，每日产出被摊薄。

### 核心规则

1. **购买当天不计产出**，次日开始产出。
2. 到期时间 = 起始时间 + 持有天数；**到期是一个事件**，到期后该卡不再产出。
3. 每日产出 = 到期本息 ÷ 持有天数（总本息等于每日产出累计，到期不额外返还）。
4. 每类卡的「额度」是**同时持有上限**，不是累计购买次数：持有期间占额度，**到期次日零点才释放**（到期当天仍占用，因此不能立刻补一张）。
5. 活跃度 = 当前**未到期**算力卡的活跃度之和；购买时活跃度 > 100 即适用 40 天新版规则（`ACT_THRESHOLD = 100`）。
6. 「自动」规则下，系统会按时间顺序为每张卡解析其购买时刻的活跃度，从而确定该用 35 天还是 40 天。

### 起算日与历史卡

「起算日」默认是今天，但**可以改成过去的某一天**，用来从头复盘一段已经发生的历史（比如从 11 月 1 日开始算）。

改的时候注意：**填的「当前余额」要对应起算日那一天**，也就是表格第一行显示的数值。当天发生的买入 MEX、买卡扣款都会在那个数值的基础上再计算一遍，所以如果把余额填成「今天」的数字、又把起算日拉到过去，会重复计算期间的所有收支。

两条规则：

1. **起算日的产出不重复累加**。表格第一行会列出当日产出（供参考），但余额就等于你输入的数值，不会再多加一次；从次日起才逐日累加。
2. **已过持有期的历史卡不参与推算**。起始日期早于起算日、且到起算日已经持有满期的卡，其结果已经体现在余额里，在「起始设置」的算力卡列表里标记为「已到期」并跳过；仍在持有期内的卡照常逐日产出。

同一天的操作顺序是：产出 → 到期 → **买入 MEX（先到账）** → 买卡扣款 → 卖出 MEX。买入放在买卡之前，是为了让当天充进来的 MEX 当天就能用来买卡。

### M 币交易与汇率

**M 币就是 MEX 的简称**——两者是同一个东西。所以交易的「数量」直接就是 MEX 数量，买卖直接加减余额：

```
买入 MEX 100 → 余额 +100
卖出 MEX  40 → 余额 −40
```

卡片顶部填两个汇率，只用来把 MEX 折算成人民币（也用来在徽章里标注这笔的成本）：

```
1 MEX 的美元价 = MEX 兑美元
美元金额 = MEX 数量 × MEX 兑美元
人民币金额 = 美元金额 × 美元兑人民币
```

举例：`MEX 兑美元 = 1.9`、`美元兑人民币 = 7.2`，则 1 MEX ≈ ¥13.68。

- 买入 100 MEX：余额 +100，徽章 `买入 MEX 100 @1.9 ≈ ¥1,368.00`
- 卖出 40 MEX：余额 −40，徽章 `卖出 MEX 40 @1.9 ≈ ¥547.20`

几个设计点：

- **汇率为空也能记账**，只是徽章上不显示 `@x` 和人民币金额，余额照样按数量加减。
- 汇率可以全局设默认值，也可以每笔单独覆盖（买在高位、卖在低位都能如实记录）。
- 表格事件列里，买入用紫色标签、卖出用绿色标签；点列表右上角 ✕ 可删除。
- 汇总里的「M 币买卖」统计的是充入 / 提出的 MEX 总量。

### 算力卡的买入扣款

「起始设置」里记录的卡，**起始日不早于起算日** 时，会在那一天从余额扣掉买入价（卡片 meta 里会写「买入扣 X MEX」），等同于一次买入事件；起始日早于起算日的卡视为当时已付款、余额已反映，不再重复扣。

### 推算顺序（每天）

```
① 结算当日产出（昨日及更早购买的卡，今日仍持有）
   └ 第一天跳过：今日产出已包含在输入的余额里
② 处理到期事件（age === 持有天数）
③ holdings 扣款（起始日 = 当天的算力卡，按买入价扣 MEX）
④ 处理当日手动购买事件（锁定额度、扣款）
⑤ 处理条件自动购买（余额 ≥ 买入价 且 有额度 → 买入 1 张，可重复至不满足）
⑥ 处理当日 M 币买卖（买入扣 MEX、卖出加 MEX）
⑦ 记录当日：产出、余额、事件、各类卡剩余额度
```

## 部署

### Cloudflare Pages

1. 把本项目目录推到 GitHub 仓库（或直接用 Wrangler 上传）。
2. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**。
3. 构建设置留空：
   - **Build command**：`（留空）`
   - **Build output directory**：`/`（仓库根目录即站点根目录；如果项目在子目录，填该子目录名）
4. 部署完成，获得 `https://<project>.pages.dev`，可绑定自定义域名。

命令行方式：

```bash
npx wrangler pages deploy . --project-name mallex-calculator
```

### Vercel

1. 推到 GitHub，Vercel → **Add New** → **Project** → 导入仓库。
2. Framework Preset 选 **Other**，Build Command 与 Output Directory 均留空。
3. Deploy 即可。

命令行方式：

```bash
npx vercel --prod
```

> 项目是纯静态文件，两个平台都不需要任何配置文件。

## 数据存储与多存档

所有输入自动保存在浏览器 `localStorage`，刷新、关掉页面、下次再打开都还在。

因为可能要给多个账号分别推算，数据被组织成**多份存档**（键名 `mallex-calc-profiles`）：

- 右上角「⌸ 我的账号」打开存档面板，每份存档保存一整套余额、算力卡、购买计划、M 币交易与汇率。
- 点存档名即切换，切换前会自动保存当前这份。
- 「+ 新建空存档」开一份干净的，✎ 改名，✕ 删除（至少要留一份）。
- 顶栏「重置」只清空**当前**存档，不影响其他存档。

需要说清楚的三点：

1. 数据只存在这台设备的这个浏览器里，**不会上传到任何服务器**，也不会在手机和电脑之间同步。
2. 清理浏览器数据、使用无痕模式、换设备，存档都会消失 —— 这是纯静态页面的固有代价，没有后端就没有云端备份。
3. 旧版本的单存档数据（`mallex-calc-v1`）会在首次打开新版本时自动迁移成一份名为「我的账号」的存档，迁移后旧键即删除。

### 跨浏览器搬运：文本串

数据不同步，但可以手动搬。存档面板底部有「导出并复制」和「导入」：

1. 在 A 浏览器点「导出并复制」，文本自动进剪贴板，同时填进下面的文本框（约 400+ 字符，含存档名、全部余额、卡、计划、M 币与汇率）。
2. 用微信 / 备忘录 / 任意方式把这串字传到 B 浏览器。
3. 在 B 浏览器打开项目页 → 存档面板 → 粘贴进文本框 → 点「导入」。

导入会**新建一份存档**并沿用原来的存档名；重名时自动加 `(1)`、`(2)`…，不会覆盖你已有的任何存档。文本串是 `JSON → UTF-8 → Base64` 的可逆编码，不是加密，别把它当密码保管。

## 已知取舍

- 每日推算用**卡片式日行**而不是表格：每行顶部是「日期 / 当日产出 / 当日余额」三列对齐，下面整行放事件、持仓、可购，内容再长也只会换行、**不会横向滚动**。窄屏字号再收一档，一屏能多看几天。
- 同一天到期的同种卡合并成一条：`到期 初1 ×3（40天）`。
- 持仓按**等级从高到低**排列（精英 → 专家以外的顺序即价格降序），一眼看到最值钱的那张。
- 顶部额度条以**今天**为准，不是区间最后一天。
- 没有把「可购」拆成独立一列：390px 宽度下必然会横向滚动，代价大于收益。
- 四张卡片（起始设置 / 今日持有 / 购买计划 / 每日推算）都能点右上角箭头折到只剩标题，点标题那整行也可以，默认全展开，折叠状态记在浏览器里、下次打开保持不变。M 币交易不在页面流里，而是右下角浮钮 + 底部浮层。
- 右下角两个小圆钮：左边那个**不在底部时朝下**（一点直达页底），**滚到 95% 以下时翻成朝上**（一点回到页顶）；右边那个是「回到今天」。
- 每行可购买部分带一个灰色「可买」前缀，说明后面那排按钮是「当天可买哪些卡」，点一下就是按当天价格买入 1 张。
- 顶栏「设置」里有两项：**省略过去数据**开关（开启后每日数据从今天那行开始，起算日到今天之前的历史行不再列出，余额仍算得准）、**重置当前存档**。
- 表格滚动时表头吸附在顶栏下方（`top` 取顶栏实时高度），随时能看见列名。
- 命中多条可购卡时，每个日期最多显示 3 个购买按钮，避免把行撑得太高。
- 「自动购买」规则为「每天最多买 1 张」，用于模拟「余额够就买」的朴素策略；如需一次买多张，请使用手动购买事件。多条规则的**先后顺序就是优先级**（排在前面的先花余额），用 ↑ ↓ 调整。
- 购买计划与 M 币交易列表按**高度**折叠（超过约 226px 就整段收起），不按条数；点「展开全部 N 条」查看。
- 添加算力卡时会校验额度（同时持有上限），超出会被拦下并提示剩余数量。
- 撤销是**全局撤销**（按输入时间），不是只撤销表格里的买入；Ctrl+Z 在输入框内保留浏览器原生行为。
